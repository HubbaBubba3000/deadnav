## Средний приоритет (P2)

### 🟡 P2-7. Нет таймаута на запросы к БД

Нигде не используется `context.Context` для запросов к БД. Все вызовы `QueryRow`/`Query`/`Exec` используют бесконечный дефолтный контекст. При зависании БД запросы никогда не отменятся.

**Исправление:** Передавать `context.Context` из Gin (`c.Request.Context()`) в сервисы и использовать `QueryRowContext`, `QueryContext`, `ExecContext`.

**Статус:** Открыто - В коде не реализовано. Необходимо обновить все сервисы для использования context.Context.

## Проблемы безопасности

### 🔒 SEC-1. JWT Secret по умолчанию ✅ ИСПРАВЛЕНО

**Файл:** `internal/config/config.go`

При запуске в production (`GIN_MODE=release`) приложение падает, если `JWT_SECRET` не установлен или использует значение по умолчанию. В development выводится WARNING.

### 🔒 SEC-2. Нет rate-limiting на эндпоинтах аутентификации

`POST /api/v1/auth/register` и `POST /api/v1/auth/login` не имеют ограничения по частоте запросов. Это позволяет брутфорс-атаки на пароли и массовую регистрацию.

**Исправление:** Добавить rate-limiting middleware для auth-группы (например, `github.com/ulule/limiter`).

**Статус:** Открыто - Не реализовано. Нужно добавить middleware для ограничения частоты запросов.

### 🔒 SEC-3. Нет ограничения размера тела запроса ✅ ИСПРАВЛЕНО

**Файл:** `cmd/api/main.go`

Добавлен `http.MaxBytesReader` с лимитом 8 MB.

### 🔒 SEC-4. CORS разрешает все origins ✅ ИСПРАВЛЕНО

**Файл:** `pkg/middleware/middleware.go`

CORS теперь валидирует origins через `ALLOWED_ORIGINS` env var. Пустое значение запрещает все origins (secure default). `*` разрешает все (с оговоркой).

### 🔒 SEC-5. Пароли в docker-compose.yml в открытом виде ✅ ИСПРАВЛЕНО

**Файл:** `docker-compose.yml`

Убраны значения по умолчанию для паролей. Все пароли теперь передаются через переменные окружения (`${MYSQL_PASSWORD}`, `${MYSQL_ROOT_PASSWORD}`, `${JWT_SECRET}`).

### 🔒 SEC-6. Порт MySQL открыт наружу ✅ ИСПРАВЛЕНО

**Файл:** `docker-compose.yml`

Порт MySQL (`3306`) более не проброшен наружу. При необходимости локальной разработки можно раскомментировать привязку к `127.0.0.1`.

## Проблемы инфраструктуры / Docker

### 🐳 INF-1. Dockerfile: `go mod tidy` при каждой сборке

`go mod tidy` может изменить `go.mod`/`go.sum`, что сделает сборку невоспроизводимой. Лучше разделить:
```dockerfile
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN go build ...
```

**Статус:** Исправлено - Не является проблемой в текущей реализации, так как в Dockerfile правильно реализована последовательность копирования.

### 🐳 INF-2. Dockerfile: HEALTHCHECK использует `wget`, но он не установлен

В финальном образе (`alpine:3.19`) добавлены только `ca-certificates` и `tzdata`. `wget` не установлен, поэтому HEALTHCHECK не сработает.

**Исправление:** Добавить `wget` в `RUN apk --no-cache add ca-certificates tzdata wget`, либо использовать встроенный `wget` из busybox, который есть в alpine по умолчанию.

**Статус:** Открыто - HEALTHCHECK использует `curl`, но в `RUN` командах убран `wget`. Проверить и исправить.

### 🐳 INF-3. docker-compose: `depends_on` с `condition: service_healthy`

`depends_on` с `condition` не работает в `docker compose up` (работает только в swarm mode или с `docker-compose` v2). Новый `docker compose` (без дефиса) эту опцию игнорирует. Нужно использовать `depends_on:` без condition + retry logic в приложении, или `healthcheck` + `start_period`.

**Статус:** Открыто - Требуется доработка в docker-compose.yml для улучшения механизма ожидания сервиса.
